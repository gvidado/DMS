# V0.10.1 历史查询与数据库部署说明

## 当前部署选择

- 目标：Windows 10、32GB内存、暂定2TB数据盘，同机PostgreSQL。
- 原包与补写目录：`D:\TelemetryHistory`。
- 数据库连接：`127.0.0.1:5432`，专用数据库`telemetry_history`，专用账号`telemetry_ingest`。
- 数据库只供服务器端程序连接，浏览器继续访问数据判读系统网页。系统可完全离线使用。

本机已检测到PostgreSQL **18.4**，安装目录`D:\Program Files\PostgreSQL\18`，服务名`postgresql-x64-18`。检测时服务停止，5432端口无响应。已有安装可使用，不需要重复安装或重新初始化其数据目录。

## 一、启动已有数据库

在Windows“服务”中找到`postgresql-x64-18`并启动；也可用管理员PowerShell运行程序目录下的：

```powershell
.\tools\启动PostgreSQL18.ps1
```

启动服务需要Windows服务管理权限。工具不会重装数据库、重置密码或修改已有数据。数据库原来监听哪些地址、现有库保存在哪个目录，也不会由此更改。

## 二、建立专用数据库与账号

已有`telemetry_history`和`telemetry_ingest`时，直接使用已有凭据配置网页；工具检测到其中任意一个已存在即保持原样，不修改密码。

新建时，在程序目录PowerShell运行：

```powershell
.\tools\初始化历史数据库.ps1
```

若本机脚本策略阻止执行，可使用Windows命令提示符运行：

```text
powershell -NoProfile -ExecutionPolicy Bypass -File ".\tools\初始化历史数据库.ps1"
```

按窗口提示输入：先输入原有`postgres`管理员密码，再为新建的`telemetry_ingest`设置密码（输入两遍）。密码在本机输入，不回显，不写入脚本或聊天。工具仅连接127.0.0.1；不创建防火墙开放规则。

安装位置不同可加`-PgBin "实际安装目录\bin"`，数据库端口不同可加`-Port 端口号`。初始化需要已有PostgreSQL管理员凭据；不能用Windows管理员权限代替数据库密码。

## 三、网页配置

1. 启动数据判读系统，用管理员账号登录。
2. 打开“系统配置 → 历史存储配置”。
3. 原包目录填写`D:\TelemetryHistory`；数据库地址127.0.0.1、端口5432、数据库telemetry_history、账号telemetry_ingest。
4. 在网页输入新设置的数据库账号密码，勾选启用数据库写入，保存配置。
5. 点击“检查并初始化历史表”，看到连接正常及历史表就绪后，即可进入历史查询。

历史表位于独立的`td_history`架构，不覆盖其他应用表。首次建表后，后台会补写已经落盘的本地历史。

停止监听时保存立即生效；监听/演示运行中按系统每120秒的统一检查周期生效。点击停止接收也会立即应用待生效存储配置。变更原包目录后，旧目录仍保留并参与补写和详情读取，**不要直接删除旧目录**。

密码按当前运行程序的Windows账号加密保存，网页不会返回已保存密码。更换运行账号或迁移电脑后，应在网页重新输入数据库密码。

## 四、使用历史查询

主页“历史查询”打开独立网页标签页。先新建试验或选择已有未结束试验，再启动监听。没有选择时，系统自动建立试验。多次启停可归于同一个试验。

按记录类型选择内部标签页，填写时间和筛选条件后查询。默认查询最近一小时，新查询会更新默认结束时间；手工指定结束时间后保持手工时间。翻页期间时间范围保持固定。

遥测历史显示精确工程值文本、原始十六进制码、质量和时间依据。通信报文包括解码层报文与网卡捕获证据，两者分层展示。可通过方向或状态区分有效新帧、重复帧、坏包、网卡接收证据。

“查看详情”显示完整UDP载荷、可识别SPP源码和原始档案JSON。导出CSV包含全部符合当前筛选条件、在导出快照中已入库的记录，不局限当前页。超长整数在CSV文件中保持精确文本，若用Excel查看，应将对应列按文本导入。

## 五、导入已有pcapng

在历史查询页展开“导入历史pcapng文件”。先确认当前SPP来源、映射与系数适用于该文件，再选择、上传并导入。原文件永久保留；已导入的参数与在线参数在查询中共用结构，但时间依据、采集方式、会话ID分别标明。

完成后点击“查询此文件”，自动使用文件原始时间范围和该导入会话筛选。历史时间可能与今天不同，不能只查最近一小时。

取消或异常退出后可重试已完整上传的文件。重试从头读取以恢复帧计数上下文，事件ID保持不变，数据库不会重复增加相同样本。同文件同配置重复上传会提示原导入编号。上传未完整完成时需要重新选文件，已上传的部分仍保留供核对。

## 六、存储与故障处理

- 数据库断连：原包继续本地归档；查询暂不可用。恢复连接后自动补写，不需要重新发送设备数据。
- 归档磁盘不可写或队列达到保护上限：明确报错并停止采集，避免把未保存的数据伪装成已保存。修复磁盘后确认状态，再恢复监听。
- 磁盘容量：页面显示剩余空间和低容量提示。永久保留不意味着2TB永远够用，应按现场实测增长率安排扩容。
- 正常退出：优先使用控制台Ctrl+C，等待程序完成落盘。直接结束进程、关机或断电可能影响尚在内存中的记录；批量间隔不是零数据丢失承诺。
- 备份：同时备份PostgreSQL数据库、全部登记的原包目录，以及程序`config`和`data/history-state`。仅备份数据库不能替代完整原包备份。
- 迁移：停采集后完整迁移上述内容，并保持或重新规划原包路径；原索引记录绝对路径，直接改盘符不会自动迁移文件。不要为了消除错误删除历史文件。

## 七、离线组件

升级包包含64位libpq客户端及依赖、许可证和建表文件，不要求浏览器联网。数据库服务器本体另附官方Windows x64离线二进制包；本机已有18.4无需安装该包。新电脑无数据库时，应先完成服务器安装和专用库初始化，再连接网页。
