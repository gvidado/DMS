# V0.10.1 数据结构与时序说明

## 模块与采集链路

网络/本系统发令 → 接收或捕获时立即取时 → 现有解码/判读引擎 → 独立归档队列 → 压缩原包分段 → PostgreSQL后台批量补写 → 历史查询。

数据库读写在后台线程或独立查询请求中进行，不在实时判读主锁内等待数据库。归档估算队列上限128MiB；文件导入主动节流。文件分段落盘并刷新后登记SHA256索引，数据库以分段为事务提交，提交成功才推进补写位置。失败保留原文与位置，使用事件ID和样本主键防止重复。

配置快照记录实际生效的监听/SPP/参数/常态规则/指令库/TC绑定，参数历史关联当时定义，不用今天的系数重算过去的工程值。快照不包含数据库密码或完整序列定义。

## 数据结构

| 表 | 内容 |
| --- | --- |
| experiment | 试验名称、起止时间、说明 |
| segment | 原包分段路径、SHA256、记录数、入库时间 |
| configuration | 实际生效的配置快照、哈希、软件版本 |
| parameter_definition | 来源命名空间、参数定义、SPP映射及配置版本 |
| event | 通信/会话/配置/指令/判据/异常等事件的统一时间和原文索引 |
| sample | 有效新帧全部参数工程值、精确整数、源码、质量及所属原包 |
| command_event | 本系统发令结果或捕获证据、指令代号/名称、端点 |
| judgment_observation | 实际判据、结果、参数实际值、引用样本及明确关联的指令事件ID |
| incident | 异常事实及人工解除状态、时间、原因和操作人 |

完整UDP载荷保存在压缩分段，数据库保存可校验的文件/行索引。历史导入还保存完整pcapng原文件、哈希、原始帧位置。新库没有完整序列定义、序列运行进度或“试验独占序列”的模型。

当前以普通索引表实现第一阶段，未宣称已经完成TB级数据分区或多年容量验收；后续可按现场增长率增加分区及分析视图，不改变事件和参数定义关联。

## 关联原则

同一步实际发出的指令与其参数判据保存显式事件ID；常态化规则显式依赖TC时记录对应命令事件。工程值样本保留原报文事件ID，支持多判据共享同一批遥测。

时间邻近只作为研究查询线索，不自动当成因果关系。系统发令结果是本地发送调用结果；监视到发送是网卡捕获证据，两者分别保存，不等同对端应答。本系统按需求不以对端确认作为发令成功条件。

## 时间定义

| 字段/依据 | 含义 |
| --- | --- |
| Time / observed_at | 原始事件时间；尽可能使用服务器同一抓包网卡时间 |
| Received / received_at | 程序取得该事件的服务器UTC时间，不是数据库提交时间 |
| ObservedTicks / ReceivedTicks | 原始.NET UTC ticks，100ns单位整数，接口以字符串返回，避免浏览器整数舍入 |
| MonotonicTicks + Boot | 同一进程内连续计时及启动标识，可辅助分析时间顺序 |
| Ordinal | 本进程事件登记顺序，不跨重启冒充统一硬件序号 |
| NPCAP_RECEIVE | 解码报文已唯一关联到对应网卡接收捕获事件 |
| NPCAP_CAPTURE | 独立的网卡收发捕获证据 |
| SOCKET_RECEIVE | Socket返回时取到的服务器精确UTC时间，尚无唯一网卡关联 |
| PCAP_CAPTURE | 原pcapng中的捕获时间；导入或回放速度不改变它 |
| UNKNOWN_CAPTURE_TIME | 原始捕获文件没有时间，保留未知标记，不能当作可信设备事件时间 |
| LOCAL_SEND_RESULT | 本系统发送调用结果时刻，区别于物理捕获时刻 |

接收取时放在返回收包之后、等待判读锁之前。Windows精确UTC时钟和高精度连续计时并行保存，数据库入库时间另列。网卡捕获与Socket报文仅在同IP/端口/载荷哈希、候选唯一时关联；重复报文无法唯一识别或缓存窗口不足时，保持SOCKET_RECEIVE，不能猜测替换时间。captureAssociated只表示关联成功，accuracyVerified仍为false。

PostgreSQL时间列支持微秒；原始ticks及文本另存以保留更细分辨率。查询同时间数据用ticks、登记顺序、事件ID和参数ID稳定翻页。不能用入库先后替代网络时序。

**1ms是现场验收目标，目前未证明目标网卡和服务器上的绝对误差已达到1ms。** 捕获时间小数位、Windows时钟分辨率、同一网卡时间来源，均不是独立精度校准。应在目标机使用可核对的共同时间参考，在代表性负载下检查偏差、抖动、抓包丢包和系统时钟调整；未关联的Socket记录单独统计。离线环境也要建立可用的时钟校准方式。

## 永久保存与恢复边界

永久保存表示没有自动过期或覆盖策略，不表示无限磁盘。原始文件和数据库都需要备份。正常退出等待归档；数据库未补写的原文可在下次启动继续补写。已完整落盘但未登记的分段可恢复索引；不完整文件保留并明确提示，不静默删除或伪装完整。

归档全局索引缺失时，可由已登记原包目录的索引重建，数据库重新核对已提交事件。索引损坏、原文件哈希不符、样本定义缺失等情况会报告原因，不跳过失败分段继续声称全量完成。
